## 1. כללי

### 1.1 רקע
המזכירה של TRUSTECH (חברה שמנהלת, מטמיעה ומיישמת מערכות מידע) עזבה. המערכת נועדה לקחת על עצמה את המשימות השוטפות שלה: לעקוב אחרי קניות וחוסרים, לתאם פגישות, לקבל פניות ולנתב אותן, לפרסם הודעות ולשמור על האווירה במשרד.

### 1.2 מטרות
- מקום אחד שכל עובד נכנס אליו לכל עניין משרדי
- שקיפות: כל אחד יודע מה חסר, מה הוזמן ומה מצב הפנייה שלו
- חיסכון בזמן למנהלים: מה שדורש טיפול מוצג להם במקום אחד, לפי עדיפות
- חיבור מלא ל-Microsoft 365 שכבר משמש את החברה

### 1.3 קהל יעד
20–100 עובדים (כרגע צוות פיתוח אחד) ו-4 מנהלים עם הרשאות מלאות.

### 1.4 מחוץ לתחום בגרסה הראשונה
שכר, דיווחי נוכחות, הנהלת חשבונות, ניהול לקוחות (CRM).

### 1.5 מונחים
| מונח | הסבר |
|---|---|
| **חוסר** | מוצר שעובד דיווח שנגמר וצריך לקנות אותו |
| **פנייה** | בקשה או דיווח על בעיה שעובד שולח לגורם מטפל |
| **SLA** | זמן הטיפול שהוגדר כיעד לכל רמת עדיפות |
| **Graph** | ממשק Microsoft Graph, שדרכו המערכת עובדת מול Outlook ו-Entra ID |
| **Entra ID** | מערכת המשתמשים של Microsoft 365 (בעבר Azure AD) |

## 2. משתמשים והרשאות

### 2.1 תפקידים
יש שני תפקידים בלבד:

| תפקיד | הרשאות |
|---|---|
| **עובד/ת** | אזור אישי; צפייה ברשימת הקניות לפי הגדרות החשיפה; דיווח חוסרים; עדכון שפריט נקנה, כולל כמות ומחיר (בלי לראות מחירים קיימים); פתיחת פניות ומעקב אחריהן; זימון פגישות; צפייה בהודעות, בספר הטלפונים ובלוח ימי ההולדת |
| **מנהל/ת** | **גישה מלאה לכל המערכת**: כל מה שמותר לעובד, וגם ניהול קטגוריות, מוצרים וחשיפה; צפייה במחירים ובדוחות; אישור קניות; טיפול בכל הפניות; ניהול סוגי פניות; פרסום הודעות; ניהול משתמשים; כל ההגדרות; יומן פעולות |

- בחברה יש כרגע **4 מנהלים**, ולכולם אותן הרשאות מלאות
- אין תפקיד נפרד של "מנהל מערכת". כל מנהל יכול לשנות הגדרות
- מנהל יכול להפוך עובד למנהל או להחזיר אותו להיות עובד. אי אפשר להוריד את המנהל האחרון שנשאר במערכת

### 2.2 התחברות
- כניסה יחידה (SSO) עם החשבון הארגוני ב-Microsoft 365, בלי סיסמה נוספת
- בכניסה הראשונה המשתמש נוצר אוטומטית במערכת, עם התפקיד "עובד"
- אפשר לקבוע תפקידים לפי קבוצות ב-Entra ID (למשל: מי שנמצא בקבוצה `Office-Managers` הוא מנהל), או ידנית במערכת
- עובד שהחשבון שלו הושבת ב-Microsoft 365 מאבד גישה מיד

### 2.3 צוותים
- כרגע יש בחברה צוות אחד: **צוות פיתוח**
- מנהל יכול להוסיף צוותים מתוך המערכת, בלי צורך בפיתוח נוסף
- הצוות משמש לזימון כל הצוות לפגישה, לחשיפה של מוצרים ולקהל של הודעות
- כל עוד יש רק צוות אחד, לא מוצגים במסכים שדות לבחירת צוות

## 3. אזור אישי ולוח בקרה

### 3.1 לוח הבקרה של העובד
| רכיב | תוכן |
|---|---|
| ברכת פתיחה | "בוקר טוב, [שם]", התאריך הלועזי והעברי |
| הפגישות שלי | הפגישות הקרובות מהיום ועד 7 ימים קדימה, מתוך Outlook |
| הפניות שלי | פניות פתוחות, הסטטוס שלהן ותגובות חדשות |
| הודעות | הודעות נעוצות והודעות שעוד לא נקראו |
| ימי הולדת | ימי ההולדת היום ובשבוע הקרוב |
| פעולות מהירות | "דיווח חוסר", "פנייה חדשה", "זימון פגישה" |

### 3.2 לוח הבקרה של המנהל
כל מה שמופיע אצל העובד, ובנוסף:
- **פניות פתוחות**, ממוינות לפי עדיפות, כשפניות שחרגו מה-SLA מסומנות באדום. כל המנהלים רואים את כל הפניות, וכל אחד יכול לקחת פנייה לטיפולו ("אני מטפל/ת")
- **חוסרים פתוחים** שממתינים לאישור או לקנייה
- **הוצאות החודש** לכל קטגוריה, לעומת התקציב
- **תזכורות** לימי הולדת שיחולו בשבוע הבא

### 3.3 הפרופיל שלי
- פרטים שמגיעים מ-Microsoft 365: שם, תפקיד, מייל, תמונה (לקריאה בלבד)
- פרטים שאפשר לעדכן: טלפון נייד, תאריך לידה והגדרות ההצגה שלו (ראו סעיף 8)
- העדפות התראות: בתוך המערכת בלבד, או גם במייל

## 4. רשימת קניות

### 4.1 קטגוריות
- קטגוריות ברירת המחדל: **מטבח**, **ציוד משרדי**, **אחר**
- מנהלים מוסיפים קטגוריות לפי הצורך: שם, סמל, צבע וסדר. אפשר גם להעביר קטגוריה לארכיון
- לכל קטגוריה מגדירים:

| הגדרה | ברירת מחדל |
|---|---|
| **צריך אישור מנהל לפני קנייה** | מטבח: **לא**, נכנס ישר לרשימת הקנייה. ציוד משרדי: **כן**. אחר וכל קטגוריה חדשה: כן |
| חשיפה | כל החברה |
| תקציב חודשי | **לא מוגדר**. מנהל יכול להגדיר אם ירצה |

### 4.2 מוצרים
| שדה | הערות |
|---|---|
| שם | חובה |
| קטגוריה | חובה |
| יחידת מידה | יחידה, חבילה, קרטון, ק"ג, ליטר |
| כמות רגילה לקנייה | ממלאת את הכמות אוטומטית כשמדווחים חוסר |
| מחיר אחרון | מתעדכן אוטומטית מכל קנייה |
| ספק או חנות מועדפים | **לא חובה**. בחירה מרשימת ספקים שמתעדכנת מעצמה, או טקסט חופשי. בכל קנייה אפשר לרשום חנות אחרת |
| תמונה והערות | לא חובה |
| חשיפה | עוברת אליו מהקטגוריה, ואפשר לשנות |

עובד שמחפש מוצר שלא קיים יכול להציע מוצר חדש. מנהל צריך לאשר את ההצעה לפני שהמוצר נכנס לרשימה הקבועה.

### 4.3 חשיפה
אפשר להגדיר חשיפה לקטגוריה או למוצר:
- **כל החברה**: כל העובדים רואים את הפריט ויכולים לדווח עליו
- **מנהלים בלבד**: לדוגמה, ציוד שמנהלים בלבד מזמינים
- **צוותים מסוימים**: לדוגמה, ציוד טכני שרק צוות התשתיות צריך

**מחירים:** רק מנהלים רואים מחירים, היסטוריה ודוחות. עובד רגיל **יכול להזין** כמה קנה וכמה זה עלה כשהוא מסמן "נקנה", אבל אחרי השמירה הוא כבר לא רואה את המחיר.

### 4.4 מחזור החיים של פריט
```
חסר ──► אושר לקנייה ──► נקנה ──► סגור
  │
  └──► נדחה (עם סיבה)
```
| שלב | מה נרשם |
|---|---|
| **חסר** | מי דיווח, מתי, הכמות המבוקשת, הערה |
| **אושר לקנייה** | מי אישר ומתי. בקטגוריות שלא צריכות אישור (כמו מטבח) השלב הזה עובר אוטומטית |
| **נקנה** | **כל עובד** יכול לסמן: הכמות שנקנתה, הסכום ששולם, איפה נקנה, צילום קבלה (לא חובה). המערכת שומרת מי קנה ומתי |
| **סגור** | הפריט חוזר להיות "במלאי" |

- **מניעת כפילויות**: אם עובד מדווח על מוצר שכבר מסומן כחסר, נוסף "+1" לדיווח הקיים
- **רשימת קנייה להדפסה או לנייד**: כל החוסרים המאושרים מסודרים לפי חנות או קטגוריה, עם תיבות סימון
- **קנייה מקבוצה**: אפשר לסמן כמה פריטים כנקנו ביחד ולהזין את הסכום הכולל של הקבלה

### 4.5 דוחות
- הוצאות לפי קטגוריה ולפי חודש, כגרף וכטבלה
- מגמת המחיר של מוצר לאורך זמן
- המוצרים שנגמרים הכי הרבה
- התראה כשמגיעים ל-80% ול-100% מהתקציב החודשי של קטגוריה (רק אם הוגדר תקציב)
- ייצוא ל-Excel

## 5. זימון פגישות (Outlook)

### 5.1 טופס זימון
| שדה | הערות |
|---|---|
| נושא ותיאור | |
| משתתפים | צוות שלם, עובדים בודדים, או צוות בלי חלק מהאנשים בו. אפשר להוסיף גם מייל חיצוני |
| משתתפים חיוניים או אופציונליים | נשלח ל-Outlook בהתאם |
| משך | 15, 30, 45 או 60 דקות, או משך אחר |
| טווח תאריכים לחיפוש | ברירת מחדל: 5 ימי העבודה הקרובים |
| מיקום | ברירת המחדל: **במשרד**. אפשר לשנות לכתובת אחרת או לפגישת Teams שהקישור שלה נוצר אוטומטית. אין במשרד חדרי ישיבות לניהול |
| חזרה | חד פעמית, יומית, שבועית או חודשית |

### 5.2 בדיקת זמינות
- המערכת שולפת את היומנים של כל המשתתפים דרך Graph (`getSchedule`), ומציגה רק אם השעה **פנויה או תפוסה**, בלי פרטי הפגישות
- תצוגה של ציר זמן: שורה לכל משתתף, ושורה מסכמת שמראה את השעות הפנויות לכולם
- **הצעות אוטומטיות**: 3–5 המועדים הטובים ביותר (דרך `findMeetingTimes`). כברירת מחדל ההצעות הן בתוך שעות העבודה הרגילות (א'–ה', 08:00–17:00). מכיוון שבפועל יש הרבה חריגות, אפשר לסמן "חפש גם מחוץ לשעות העבודה" ולבחור כל יום ושעה
- אם אין שעה שבה כולם פנויים, המערכת תציג את המועדים שבהם הכי מעט משתתפים חיוניים תפוסים

### 5.3 שליחה ומעקב
- המערכת יוצרת אירוע ביומן של מי שמזמן, ו-Outlook שולח את הזימון לכל המשתתפים כמו זימון רגיל
- תשובות המשתתפים מוצגות במערכת: אישרו, דחו, אולי, טרם ענו
- עדכון או ביטול של הפגישה מהמערכת מתעדכנים גם ב-Outlook

### 5.4 דרישות מול Microsoft
- רישום אפליקציה ב-Entra ID (App Registration)
- הרשאות: `Calendars.ReadWrite`, `User.Read.All`, `OnlineMeetings.ReadWrite` (לפגישות Teams), `Mail.Send` (להתראות)
- **צריך שמנהל ה-tenant יאשר את ההרשאות (Admin consent)**

| קבצים מצורפים | תמונות ומסמכים, עד 10MB לקובץ |

### 6.2 קטגוריות ועדיפויות
| קטגוריה (התחלתית) | עדיפות ברירת מחדל | הערות |

| בקשת ציוד | רגילה | |
| תחזוקת משרד (מזגן, תאורה, ניקיון) | רגילה | |
| בקשה מנהלית (אישורים, מסמכים) | רגילה | |
| **שכר** (תלוש, שעות, החזרי הוצאות) | רגילה | **פנייה חסויה**: רק מי שפתח אותה והמנהלים רואים אותה. היא לא מופיעה בדוחות שמראים פירוט לפי עובד |
| אחר | נמוכה | |

- הנמען של כל הפניות הוא **המנהלים**
- **רק מנהלים** יכולים להוסיף סוגי פניות, לערוך אותם או להעביר לארכיון. לכל סוג מגדירים עדיפות ברירת מחדל, ואפשר לסמן אותו כחסוי

### 6.3 רמות עדיפות ו-SLA
| רמה | צבע | SLA לתגובה ראשונה (ברירת מחדל) |
|---|---|---|
| דחופה | אדום | 4 שעות עבודה |
| גבוהה | כתום | יום עבודה אחד |
| רגילה | כחול | 3 ימי עבודה |
| נמוכה | אפור | 5 ימי עבודה |

הערכים האלה אושרו. השעון של ה-SLA סופר רק שעות עבודה רגילות (א'–ה', 08:00–17:00), ולא סופר שבתות וחגים. מנהל יכול לשנות את הערכים.

### 6.4 סטטוסים
```
חדשה ──► בטיפול ──► טופלה ──► סגורה
              │  ▲
              ▼  │
       ממתינה למידע
```
- כשהסטטוס הוא "ממתינה למידע", שעון ה-SLA נעצר
- 3 ימים אחרי שפנייה סומנה "טופלה" היא נסגרת אוטומטית, אלא אם פותח הפנייה הגיב
- פותח הפנייה יכול לפתוח אותה מחדש

### 6.5 טיפול
- שרשור תגובות, עם אפשרות להערה פנימית שרק הגורמים המטפלים רואים
- מנהל לוקח פנייה לטיפולו, או מעביר אותה למנהל אחר עם הסבר
- היסטוריה מלאה של שינויים בסטטוס, בעדיפות ובנמען
- **הסלמה**: כשעוברים את ה-SLA, כל המנהלים מקבלים התראה והפנייה מסומנת בלוח הבקרה
- דירוג שביעות רצון בסגירה, 1–5 כוכבים (לא חובה)

### 6.6 תצוגות
- **הפניות שלי**: אלה שפתחתי
- **לטיפולי** (מנהלים): פניות שנשלחו אליי או שלקחתי לטיפולי

### 8.2 חישוב התאריך העברי
החישוב נעשה עם הספרייה `@hebcal/core`. כללים:
- **אדר**: מי שנולד באדר בשנה רגילה חוגג בשנה מעוברת באדר ב'. מי שנולד באדר א' או באדר ב' חוגג באותו אדר בשנה מעוברת, ובאדר בשנה רגילה

### 8.3 לוח ימי ההולדת
- תצוגה חודשית (לוח שנה) ורשימה של ימי ההולדת הקרובים
- כל יום הולדת מוצג עם שני התאריכים, ולצדו סימן שמראה לפי איזה תאריך העובד חוגג
- סינון לפי צוות
- מעבר בין חודשים לועזיים לחודשים עבריים

### 8.4 ביום ההולדת
**לעובד/ת שחוגג/ת:**
- בכניסה הראשונה באותו יום קופץ חלון ברכה אישי, עם הנפשה עדינה. לדוגמה:
  > 🎂 **מזל טוב, [שם]!**
  > כל צוות TRUSTECH מאחל לך שנה של בריאות, הצלחה ושמחה.
- יש כמה נוסחים שמתחלפים, והמנהלים יכולים לערוך אותם
- **קיר ברכות** אישי עם הברכות שחברי הצוות שלחו

**לכל העובדים, במסך הבית:**
- המסך מקושט ב**בלונים** שעולים מלמטה, ב**זיקוקים** ובכרזה:
  > 🎉 **היום חוגגים יום הולדת ל[שם]!**
- ההנפשה המלאה מוצגת **פעם אחת ביום לכל משתמש**. אחר כך נשארים רק הכרזה ובלונים קטנים בפינה
- כשכמה עובדים חוגגים באותו יום, כל השמות מופיעים בכרזה
- כפתור **"שלח/י ברכה"** שמוסיף את הברכה לקיר הברכות של העובד ושולח לו התראה
- **נגישות**: משתמש שהגדיר במערכת ההפעלה "צמצום תנועה" (`prefers-reduced-motion`) יראה עיצוב סטטי, בלי הנפשה

**יום הולדת בשבת או בחג:**
- הכרזה מוצגת ביום העבודה הקודם, עם נוסח מתאים: "יום הולדת שמח לקראת שבת!"

### 8.5 ותק בחברה (אפשרות, כבויה כברירת מחדל)
- מנהל יכול להפעיל בהגדרות את האפשרות "ציון ותק"
- כשהיא פעילה, ממלאים לכל עובד תאריך תחילת עבודה. ביום השנה המערכת מציגה כרזה עם הנוסח "🎉 [שם] חוגג/ת היום X שנים ב-TRUSTECH!", בעיצוב דומה ליום הולדת אבל צנוע יותר

### 8.6 למנהלים
- תזכורת בלוח הבקרה ובמייל 7 ימים לפני יום ההולדת: "בשבוע הבא יום ההולדת של [שם] (כ"ג בכסלו)"

### 13.1 הגדרת החיבורים במקום אחד
את כל פרטי החיבור מגדירים **פעם אחת, בקובץ אחד**: `.env` בשרת, או משתני סביבה בענן. כל המערכת קוראת אותם משם:
- פרטי האפליקציה ב-Microsoft Entra ID: Tenant ID, Client ID, Client Secret
- כתובת המייל שממנה המערכת שולחת הודעות
- הכתובת של בסיס הנתונים
- פרטי רכז/ת הנגישות, שיוצגו בהצהרת הנגישות

הקובץ `.env.example`, עם הסבר בעברית ליד כל שדה, יהיה חלק מהפרויקט. בלי החיבורים האלה המערכת תרוץ במצב הדגמה, עם משתמשים לדוגמה, כך שאפשר לבדוק אותה עוד לפני שמגדירים את החיבור ל-Microsoft.

```
דפדפן ──► Next.js (ממשק + API) ──► PostgreSQL
                  │
                  └──► Microsoft Graph ──► Outlook / Entra ID / Teams
```

אין תאריך יעד, והמטרה היא להתקדם **מהר ככל האפשר**. כל שלב יועלה כשהוא מוכן לבדיקה, ואפשר יהיה לנסות אותו במצב הדגמה עוד לפני החיבור ל-Microsoft.

| שלב | תוכן | תוצר |
|---|---|---|
| **1. תשתית** | פרויקט, Docker, בסיס נתונים, SSO, משתמשים, צוותים, הרשאות, מבנה העיצוב והניווט, ספר טלפונים | אפשר להיכנס ולראות את ספר הטלפונים |
| **2. קניות** | קטגוריות, מוצרים, חשיפה, דיווח חוסרים, אישור, קנייה, דוחות בסיסיים | רשימת קניות עובדת |
| **3. פניות** | פתיחה, ניתוב, סטטוסים, תגובות, SLA, הסלמה, התראות | מערכת פניות עובדת |
| **4. פגישות** | חיבור ל-Graph, בדיקת זמינות, שליחת זימון, מעקב תשובות | זימונים שמגיעים ל-Outlook |
| **5. קהילה ושיפורים** | לוח הודעות, ימי הולדת עם קישוטים, לוחות בקרה מלאים, דוחות, נגישות, ליטוש | גרסה 1.0 |

## 16. רעיונות לשלבים הבאים
- **הזמנת חדרי ישיבות**: חדרים כמשאבים ב-Outlook, ותצוגה של מה תפוס ומה פנוי
- **ניהול אורחים וחבילות**: רישום מבקרים צפויים, והתראה לעובד כשהגיעה חבילה בשבילו
- **ניהול ציוד ומלאי**: מחשבים ומסכים, מי מחזיק במה, תאריכי אחריות
- **בקשות חופשה**: בקשה, אישור מנהל, ורישום ביומן הצוות
- **בוט Teams**: לדווח חוסר או לפתוח פנייה ישירות מתוך Teams
- **אפליקציה לנייד (PWA)**: התקנה על מסך הבית והתראות push
- **תזכורות חוזרות**: למשל "להזמין מים כל יום א'", "לחדש מנוי חניה"
- **סקרים קצרים** לעובדים, למשל "מה להזמין לארוחת צהריים של יום שישי?"

## 17. נשאר להגדיר בסוף הפיתוח
את הפרטים האלה מגדירים במקום אחד (סעיף 13.1), אחרי שהמערכת מוכנה:
1. **Microsoft 365**: רישום האפליקציה ב-Entra ID ואישור ההרשאות על ידי מנהל ה-tenant
2. **תיבת דואר** שממנה יישלחו המיילים של המערכת
3. **אחסון**: ענן (Azure / Render) או שרת פנימי. המערכת מוכנה לשתי האפשרויות
4. **רכז/ת נגישות**: שם ופרטי קשר להצהרת הנגישות
5. **צבעי מותג רשמיים** (לא חובה): אם יש, מחליפים בקובץ אחד
